# RD$89 direct contact release gate

This change is a separate, one-time purchase for one verified worker and one verified employer. It does not change the RD$299/30-day Workspace or RD$149 Featured Opportunity products. Checkout is closed by default, and this commit does not create a Stripe product or change production.

## Before production activation

1. Apply `supabase/migrations/202610141300_direct_contact_orders.sql` after the existing Workspace migrations. Confirm RLS is enabled, `anon` and `authenticated` have no table privileges, `service_role` has table access, the owner/worker index exists, and pending/session/payment-intent/event uniqueness constraints exist. Keep a recoverable backup. The migration is additive; it does not modify historical orders or worker rows.
2. In the existing **live Stripe account**, search active products and prices for an existing **one-time DOP 8,900 minor-unit** price for Contacto Directo. Reuse a matching price if present. Otherwise create a new product and one-time price without changing historical products, prices, or subscriptions. Confirm the price is active, `type=one_time`, `currency=dop`, `unit_amount=8900`, and `livemode=true`. The server rechecks these fields before creating Checkout. Do not substitute a recurring price or a test-mode price.
3. Keep the existing signed webhook at `/api/stripe/webhook`. Subscribe it to `charge.dispute.created` in addition to the existing `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, and `charge.refunded` events. Verify the live webhook destination and signing secret match the same live Stripe account as `STRIPE_SECRET_KEY`. A 200 response by itself does not prove a signing-secret match.
4. Configure these **Netlify production** environment variables for site `listord-2` after the preceding checks: `STRIPE_DIRECT_CONTACT_PRICE_ID=price_...` (the verified live RD$89 price), `DIRECT_CONTACT_READ_ENABLED=true`, `DIRECT_CONTACT_CHECKOUT_ENABLED=true`, `DIRECT_CONTACT_LIVE_PAYMENTS_ENABLED=true`, and `NEXT_PUBLIC_DIRECT_CONTACT_ENABLED=true`. Preserve `APP_ORIGIN=https://listordapp.com`, the existing live Stripe keys, Workspace variables, and Featured variables. `NEXT_PUBLIC_DIRECT_CONTACT_ENABLED` is compiled into the client bundle, so a new build is required. Keep all new gates unset or false until deployment is authorized and prerequisites pass.
5. Deploy the approved commit only after the migration and Stripe checks. Verify free browsing, a protected anonymous contact request, both offers on desktop/mobile, the RD$89 price on Stripe Checkout using read-only Stripe configuration checks, and the unchanged RD$299/RD$149 gates. No real payment is required or authorized for this checkpoint. The first real customer payment remains the first live end-to-end fulfillment check.

## Fulfillment and recovery

The server binds Checkout metadata and the order row to the authenticated employer and selected worker. Only a signed, fully paid, live-mode Checkout event with DOP 8,900 can mark that order paid. Contact routes query the exact owner/worker pair on every attempt. Checkout returns and browser events never grant access. `charge.refunded` and `charge.dispute.created` revoke access; disputed purchases stay revoked pending owner review, even if the dispute later closes. Duplicate events are idempotent. If the new table or Stripe configuration is unavailable, checkout fails closed. If checkout needs to be paused after purchases, disable `DIRECT_CONTACT_CHECKOUT_ENABLED` and the public offer while retaining `DIRECT_CONTACT_READ_ENABLED=true` so legitimate prior purchases remain accessible.

Do not reverse this migration blindly: it stores financial and entitlement history. Roll back the application first if needed, then reconcile any paid direct orders before changing database access.
