# Legacy worker ownership and consent — production procedure

Status: ready for individual cases; **no legacy owner or consent has been inferred or recorded**. An approved historical directory listing is a content review, not proof of identity, current availability, permission for Express outreach, or agreement to be hired.

1. Receive a request from the worker through a private support channel. Record the requested profile ID, the claimant's verified Supabase Auth user ID, the operator, the date, and an opaque case reference in a restricted case record. Keep identity documents and contact details out of the public database, URLs and analytics.
2. Check independent evidence connecting the claimant to the *specific profile*, including any shared-phone cases. A phone number, email address alone, old edit token, public profile data, or possession of an availability link is insufficient. If evidence conflicts, stop and leave the profile unlinked. Ask a second reviewer to resolve disputed or shared-phone cases.
3. Ask the worker to confirm that this Auth account should control this profile. Record that exact instruction in the private case record. In `/admin/marketplace`, link only that profile ID to that confirmed Auth ID, with the case reference and operator. The API checks that Auth confirmed the account; the service-only RPC writes an audit row and refuses replacement of an existing owner. Do not approve a pending profile as part of this step.
4. If the approved worker separately requests a private availability link, issue it only after ownership is linked. Deliver the one-time link privately to the verified owner; a new link revokes the previous link. The worker must personally mark availability or pause it. A link request is not an availability confirmation.
5. Express WhatsApp outreach requires another, revocable action by that signed-in owner in `/oportunidades`: “Acepto recibir invitaciones Express por WhatsApp.” Record the current `express-v1` consent only through the authenticated marketplace action. Sending a link, linking ownership, or checking availability does **not** create Express consent. A YES response to an opportunity must likewise come from that owner; provider acceptance is not YES.
6. Before enabling matching or outreach, verify the row still has the same owner, content approval, fresh availability, and unrevoked Express consent. If a worker disputes ownership or contact, pause the profile and outreach, preserve the audit trail, and resolve the case without silently moving ownership.

The 2.0 API now refuses availability-link issuance for unowned profiles. Confirmed-availability matching and contact also require a linked owner. The existing public directory remains a free historical listing with explicit “confirm availability” copy; it does not claim that owner identity or availability is current. Keep `WORKER_AVAILABILITY_RENEWAL_ENABLED`, `MARKETPLACE_ENABLED`, and `EXPRESS_ENABLED` false until real workers complete this process and provider acceptance is recorded.

**Case completion evidence:** private case reference, worker ID, confirmed Auth ID, independent proof and worker instruction, operator (second reviewer for disputed/shared-phone cases), audit row ID, link issuance/delivery if requested, worker's availability confirmation, and separate Express consent if requested. Never paste evidence contents into the audit reference field.
